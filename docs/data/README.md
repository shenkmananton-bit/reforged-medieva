# Данные игры: как устроен крейт `rm_data`

Этот раздел объясняет простыми словами, как игра читает текстовые файлы
из папки `data/`. Руководство для моддеров (что и как писать в файлах)
лежит отдельно, в [`docs/modding/`](../modding/README.md).

## Зачем это нужно

В Medieval II почти всё, что можно поменять в игре, лежит в обычных
текстовых файлах: статы юнитов, фракции, постройки. Мы сохраняем эту идею:
любой игрок может открыть файл в блокноте, поправить цифру и сразу увидеть
результат. Крейт `rm_data` отвечает за то, чтобы:

1. прочитать такой файл;
2. превратить его в обычные структуры Rust, с которыми удобно работать
   остальному коду (боёвке, ИИ, интерфейсу);
3. если в файле ошибка, сказать **в каком файле, на какой строке и что не так**.

## Карта файлов

| Файл | Что делает |
|---|---|
| `crates/rm_data/src/lib.rs` | Точка входа. `GameData::load_dir` загружает всю папку и проверяет связи между файлами. |
| `crates/rm_data/src/lexer.rs` | Первый проход: режет текст на строки «ключ значение», выкидывает комментарии. |
| `crates/rm_data/src/record.rs` | Второй проход: собирает строки в записи (юнит, фракция) и разбирает значения (числа, `yes`/`no`, списки). |
| `crates/rm_data/src/unit.rs` | Формат `export_descr_unit.txt`: структура `Unit` и её части. |
| `crates/rm_data/src/faction.rs` | Формат `descr_sm_factions.txt`: структура `Faction`. |
| `crates/rm_data/src/error.rs` | Ошибки `DataError` (файл, строка, причина) и их сборщик. |
| `crates/rm_data/src/bin/rm_modcheck.rs` | Маленькая программа для моддеров: проверяет папку данных и печатает ошибки. |
| `crates/rm_data/tests/parsing.rs` | Тесты: правильные файлы, неправильные файлы и тексты ошибок. |

Подробнее о каждом шаге — в [how-parsing-works.md](how-parsing-works.md).

## Как этим пользоваться из кода

```rust
use std::path::Path;
use rm_data::GameData;

let data = GameData::load_dir(Path::new("data"))?;
let levy = data.unit("Village Levy").unwrap();
println!("{} солдат, атака {}", levy.soldier.count, levy.primary_weapon.attack);
```

Если нужен только один файл, есть `load_units(path)` и `load_factions(path)`,
а для текста, который уже в памяти, — `parse_units(text, path)` и
`parse_factions(text, path)` (путь нужен только для сообщений об ошибках).

## Как проверить данные руками

```sh
cargo run -p rm_data --bin rm_modcheck -- data
```

Программа выведет либо `Всё в порядке: юнитов N, фракций M.`, либо список
ошибок вида:

```
data/export_descr_unit.txt:31: в `stat_pri`: атака должно быть числом, а написано `five`
```

А ещё она предупредит о полях, которые игра пока не понимает: такие поля не
ломают загрузку, но и ни на что не влияют.

## Главные решения

- **Без внешних библиотек.** Формат простой, ручной разбор занимает пару сотен
  строк и даёт полный контроль над текстами ошибок.
- **Собираем все ошибки сразу.** Парсер не останавливается на первой ошибке,
  чтобы моддер не запускал игру по десять раз.
- **Неизвестные поля не теряются.** Они попадают в `extra` у юнита или фракции.
  Так моды с новыми полями загружаются, а код, который появится позже,
  сможет эти поля прочитать.
- **Сообщения на русском**, в формате `файл:строка: причина`, который понимают
  редакторы кода (по нему можно кликнуть и перейти к строке).
- **Две кодировки, как в оригинале:** UTF-8 и Windows-1252 (`decode_text` в
  `lib.rs`). Если файл не является правильным UTF-8, он читается как Windows-1252.
- **Правила совместимости** взяты из [контракта моддинга](../adr/modding-contract.md):
  оригинальный синтаксис, новые поля только необязательные, новое в файлах `descr_rm_*`.
- **Данные в `data/` — наши собственные заглушки.** Файлы оригинальной игры в
  репозиторий не кладём; совместим только формат.

## Что дальше

- Загрузка данных в ECS (после того как появится `rm_core`).
- Остальные файлы: `export_descr_buildings.txt`, `descr_strat.txt` и другие.

- Столбец в сообщениях об ошибках и режим «пропустить битую запись и
  продолжить», которые требует контракт моддинга (правило 6).
- Файл `descr_rm_faction_clusters.txt` для дипломатических кластеров.
