# Аллокаторы кадра (арены)

Код: `crates/rm_core/src/memory.rs`.

## Зачем

Каждый кадр игре нужна куча временных данных: список видимых юнитов, найденные пути, команды для отрисовки. Если выделять их обычным `Vec`/`Box`, каждое выделение — это обращение к системному аллокатору, а память разбросана по куче.

Арена работает иначе: берёт один большой кусок памяти и выдаёт из него «отрезки», просто сдвигая указатель. Освобождать по одному нельзя, зато в конце кадра всё освобождается одной операцией `reset()`.

```
блок арены: [ Pos | Pos | путь........ | строка | ░░░░░ свободно ░░░░░ ]
                                                ^ смещение
reset():    [ ░░░░░░░░░░░░░░░░░░░░ всё свободно ░░░░░░░░░░░░░░░░░░░░░ ]
            ^ смещение = 0
```

## Как пользоваться

```rust
use rm_core::Arena;

let mut arena = Arena::with_capacity(1024 * 1024);   // 1 МБ

// В течение кадра:
let p = arena.alloc(Pos { x: 1.0, y: 2.0 });            // &mut Pos
let ids = arena.alloc_slice_copy(&[1u32, 2, 3]);        // &mut [u32]
let squares = arena.alloc_slice_fill_with(10, |i| i * i);
let name = arena.alloc_str("Константинополь");

// В конце кадра (компилятор не даст вызвать, пока жива хоть одна ссылка):
arena.reset();
```

### Две арены, которые меняются местами: `FrameArenas`

Иногда данные кадра нужны и в следующем кадре: например, позиции прошлого шага для интерполяции или команды, которые рендер читает с отставанием в кадр.

```rust
use rm_core::FrameArenas;

let mut frames = FrameArenas::with_capacity(4 * 1024 * 1024);
loop {
    frames.begin_frame();             // позапрошлая арена очищается и становится текущей
    let now = frames.current();       // пишем данные этого кадра
    let before = frames.previous();   // данные прошлого кадра ещё живы
    // ...
}
```

## Важные правила

- **`Drop` не вызывается.** Арена просто забывает память. Кладите туда простые данные: числа, `Copy`-структуры, срезы. `String` или `Vec` внутри арены не освободят свою память.
- **Одна арена — один поток.** Арену можно передать в другой поток (`Send`), но нельзя делить между потоками (`Sync` нет). Для параллельных задач заводите арену на каждый поток.
- **Арена растёт сама.** Если за кадр место кончилось, она берёт ещё блок, вдвое больше. На `reset()` блоки сливаются в один общий, и следующий кадр уже помещается в один блок.
- **Статистика для бюджетов памяти:** `used()` — сколько выдано с последнего сброса, `peak()` — максимум за всё время, `capacity()` — сколько арена держит у системы. Эти числа помогут подобрать стартовый размер под бюджеты из [docs/adr/budgets.md](../adr/budgets.md).

## Скорость

Выделение `Pos` из арены — около 9 нс, `Box::new(Pos)` — 13–19 нс, и это без учёта освобождения, которое у арены почти бесплатно (подробности в [benchmarks.md](benchmarks.md)). Главный выигрыш даже не в скорости выделения, а в том, что все временные данные кадра лежат рядом в памяти.
