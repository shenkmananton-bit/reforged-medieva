# Детерминизм: ГСЧ, фиксированный шаг, своя математика, хеш состояния

Код: `crates/rm_core/src/sim/` и `crates/rm_core/src/dmath.rs`.
Правила для всей симуляции: [docs/adr/determinism.md](../adr/determinism.md).

## Зачем

Реплей — это не видео, а seed плюс список команд игрока. Чтобы при воспроизведении битва прошла **точно так же**, симуляция должна давать одинаковый результат до последнего бита: на любом числе потоков, а в будущем и на разных компьютерах. Ядро даёт для этого четыре инструмента.

## 1. Случайные числа: `Rng` и `random_u64`

### Почему не обычный генератор

Если 8 потоков берут числа из одного общего генератора, то какой солдат какое число получит, зависит от того, какой поток успел первым. Реплей разойдётся.

### Счётный ГСЧ

Число вычисляется как функция от ключа: `(seed, поток, шаг, сущность, номер броска)`. Неважно, на каком потоке и в каком порядке считается солдат: для него на шаге 120 выпадет одно и то же.

```rust
use rm_core::sim::{Rng, RngStream, random_u64};

// Вариант 1: генератор для сущности на этом шаге (удобно в системах)
let mut rng = Rng::for_entity(seed, RngStream::COMBAT, tick, entity.to_bits());
let hit = rng.chance(35, 100);          // 35% попадания, без float
let dmg = rng.range_i32(5, 12);         // от 5 до 12 включительно
let roll = rng.below(6);                // 0..6

// Вариант 2: одно число без состояния
let x = random_u64(seed, RngStream::MORALE, tick, entity.to_bits(), 0);
```

**Потоки случайности** (`RngStream::COMBAT`, `MORALE`, `BATTLE_AI`, `CAMPAIGN_AI`, `CAMPAIGN_EVENTS`, `PROJECTILES`) разделяют назначение. Если в систему морали добавят ещё один бросок, числа в бою от этого не сдвинутся.

### Как устроено

- Перемешивание ключа — финализатор SplitMix64, цепочкой по частям ключа.
- Последовательный генератор — xoshiro256\*\* (быстрый, 32 байта состояния). Его состояние можно сохранить (`state()`) и восстановить (`from_state()`).
- `below(n)` — метод Лемира: равномерно, без перекоса «по модулю».
- Только целочисленные операции, поэтому результат одинаков везде.

Тест `keyed_random_is_stable_and_distinct` фиксирует конкретные значения. Если он упал, алгоритм поменялся, и все старые реплеи разойдутся. Менять такое можно только осознанно.

## 2. Фиксированный шаг: `FixedTimestep`

Рендер рисует кадры с любой частотой, а битва всегда считается шагами по **50 мс (20 Гц)**.

```rust
use rm_core::FixedTimestep;

let mut time = FixedTimestep::battle();      // 20 Гц
// каждый кадр:
let steps = time.advance(frame_dt);          // сколько шагов выполнить сейчас
for _ in 0..steps {
    simulate(&mut world, time.step_seconds() /* всегда 0.05 */);
}
let alpha = time.alpha();                    // 0..1 — для плавной картинки между шагами
```

- Время копится в **целых наносекундах**, поэтому за часы игры не набегает ошибка, как было бы с `f32`.
- **Защита от «спирали смерти»:** если компьютер не успевает, за кадр выполняется не больше 5 шагов (`with_max_steps`), а лишнее время отбрасывается. Игра замедляется, но не зависает.
- `alpha()` — только для рендера. Симуляция его не читает.

## 3. Математика: `rm_core::dmath`

`f32::sin`, `cos`, `atan2` из стандартной библиотеки вызывают системную математическую библиотеку. На Windows и Linux последний бит результата может отличаться. Поэтому в коде симуляции используем:

```rust
use rm_core::dmath;
let (s, c) = dmath::sin_cos(angle);
let heading = dmath::atan2(dy, dx);
let len = dmath::sqrt(dx * dx + dy * dy);
```

Внутри только `+ - * /` и `round`, которые стандарт IEEE 754 округляет одинаково везде. Считаем в `f64` рядами Тейлора после сведения угла к диапазону [-π/4, π/4], результат возвращаем в `f32`. Точность около 1e-7, тесты сверяют с `std` на тысячах точек.

Если понадобится ещё функция (`exp`, `ln`, `pow`), её добавляет агент ядра по тому же принципу.

## 4. Хеш состояния: `StableHasher` и `World::hash_component`

Для контрольных точек реплея (раз в секунду игрового времени) нужен хеш мира, одинаковый везде. Стандартный `DefaultHasher` не подходит: его алгоритм может поменяться в новой версии Rust.

```rust
#[derive(Hash)]
struct Hp(u16);

let h: u64 = world.hash_component::<Hp>();   // хеш всех Hp вместе с id сущностей
```

- Алгоритм FNV-1a (64 бит). Числа записываются в little-endian явно, `usize` всегда расширяется до 64 бит.
- Хеш считается **отдельно по типам компонентов**. При расхождении реплея сразу видно, какой компонент разошёлся первым.
- У `f32` нет `Hash`. Для таких компонентов реализуйте `Hash` вручную через `to_bits()`.

## Проверка

Тест `same_commands_same_hash` (`src/ecs/world.rs`) прогоняет один сценарий с параллельными системами и случайностью на 1, 4 и 8 потоках и сравнивает хеши. Это уровень D2 из ADR по детерминизму.
