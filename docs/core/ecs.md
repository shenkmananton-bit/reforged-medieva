# ECS: как хранятся солдаты, отряды и армии

Код: `crates/rm_core/src/ecs/`. Почему так, а не иначе: [docs/adr/ecs.md](../adr/ecs.md).

## Идея в трёх словах: сущность, компонент, система

- **Сущность (`Entity`)** — просто номер. У самой сущности нет данных, это «паспорт» солдата.
- **Компонент** — кусочек данных: позиция, скорость, здоровье, мораль, «это кавалерия». Любая обычная Rust-структура уже может быть компонентом.
- **Система** — функция, которая обходит все сущности с нужными компонентами и что-то с ними делает. Например, система движения берёт всех, у кого есть `Pos` и `Vel`.

Сравнение с привычным подходом:

| Привычные объекты | ECS |
|---|---|
| `class Soldier { pos, vel, hp, morale, ... }`, у каждого свой кусок памяти где-то в куче | Все позиции в одном массиве, все скорости в другом |
| Чтобы сдвинуть 10 000 солдат, процессор прыгает по 10 000 адресам | Процессор читает два массива подряд, на 100 000 солдат это примерно в 20 раз быстрее (см. [benchmarks.md](benchmarks.md)) |
| Добавить свойство — менять класс | Добавить компонент — `world.insert(e, Cavalry)` |

## Как лежит память: архетипы

Сущности с **одинаковым набором** компонентов собираются в одну таблицу — **архетип**. Строка таблицы — сущность, колонка — тип компонента.

```
Архетип {Pos, Vel, Hp}                Архетип {Pos, Vel, Hp, Cavalry}
 строка | Entity | Pos   | Vel | Hp     строка | Entity | Pos   | Vel | Hp | Cavalry
 0      | 3v0    | 10,4  | 1,0 | 100    0      | 7v0    | 50,2  | 3,0 | 80 | ·
 1      | 4v0    | 11,4  | 1,0 | 95     1      | 9v1    | 52,2  | 3,0 | 80 | ·
 2      | 8v0    | 12,4  | 1,0 | 100
```

Каждая колонка — отдельный непрерывный массив (`BlobVec` в `blob.rs`). Так устроен Structure of Arrays (SoA).

`Cavalry` — пустая структура («тег»). Она не занимает ни байта, но делит солдат на разные архетипы, и запрос `&Cavalry` выбирает только конницу.

### Где лежит конкретная сущность

`Entities` (`entity.rs`) хранит для каждого номера: поколение и «адрес» = (номер архетипа, номер строки). Поэтому `world.get::<Hp>(e)` — это два обращения к массиву, без поиска.

### Поколения: защита от «висячих» ссылок

`Entity` = индекс слота + поколение. Когда отряд погибает, его слот освобождается, а поколение увеличивается. Если ИИ хранил «цель атаки = 5v0», а слот 5 уже занят новым отрядом 5v1, то `world.get(цель)` вернёт `None`, а не чужой отряд.

## Основные операции

```rust
let mut world = World::new();

// Создать. Один компонент тоже пишется кортежем: (Hp(100),)
let e = world.spawn((Pos { x: 0.0, y: 0.0 }, Vel { x: 1.0, y: 0.0 }, Hp(100)));

// Много одинаковых сразу (быстрее, память выделяется один раз)
let army = world.spawn_batch((0..1000).map(|_| (Pos::default(), Hp(100))));

// Прочитать / изменить один компонент
let hp: Option<&Hp> = world.get::<Hp>(e);
if let Some(hp) = world.get_mut::<Hp>(e) { hp.0 -= 10; }

// Добавить / снять компонент (сущность переезжает в другой архетип)
world.insert(e, Cavalry);
let old: Option<Cavalry> = world.remove::<Cavalry>(e);

// Удалить
world.despawn(e);
```

### Запросы

Запрос описывается типом. Он перечисляет, какие компоненты нужны и как (чтение или запись):

| Что пишем | Что получаем | Условие |
|---|---|---|
| `&T` | `&T` | у сущности должен быть `T` |
| `&mut T` | `&mut T` | у сущности должен быть `T` |
| `Option<&T>` / `Option<&mut T>` | `Some`, если есть, иначе `None` | не фильтрует |
| `Entity` | номер сущности | не фильтрует |
| `(A, B, …)` | кортеж, до 8 элементов | все условия сразу |

```rust
// Только чтение: можно через &World
let total_hp: u32 = world.query::<&Hp>().map(|h| h.0 as u32).sum();

// С изменением: нужен &mut World
for (pos, vel) in world.query_mut::<(&mut Pos, &Vel)>() {
    pos.x += vel.x;
}

// С номером сущности и необязательным компонентом
for (e, hp, morale) in world.query::<(Entity, &Hp, Option<&Morale>)>() { /* ... */ }
```

Запрос обходит архетипы по очереди. Для каждого подходящего он один раз берёт указатели на начала нужных колонок и дальше просто идёт по строкам. Обход 100 000 сущностей `pos += vel` занимает 25–35 мкс.

Запрос `(&mut Hp, &Hp)` (одно и то же и на запись, и на чтение) нарушил бы правила Rust. Такой запрос сразу паникует с понятным сообщением.

### Параллельный обход

```rust
world.par_for_each_mut::<(&mut Pos, &Vel)>(&jobs, 1024, |(p, v)| {
    p.x += v.x;
});
```

Строки режутся на куски по 1024 и раздаются потокам [системы задач](jobs.md). Каждую строку обрабатывает ровно один поток, поэтому `&mut` безопасен.

Важно для реплеев: порядок обработки строк не определён. Функция должна менять **только свою** сущность. Случайность берите из `Rng::for_entity` (см. [determinism.md](determinism.md)), а не из общего генератора.

## Что внутри, по файлам

| Файл | Что там |
|---|---|
| `entity.rs` | `Entity`, выдача и переиспользование номеров (стек свободных слотов) |
| `component.rs` | трейт `Component` и реестр типов: какой номер у типа, его размер и деструктор |
| `blob.rs` | `BlobVec`: колонка без типа (массив байтов с известным размером элемента) |
| `archetype.rs` | `Archetype`: колонки + список сущностей + кэш переходов «добавили/сняли компонент» |
| `bundle.rs` | `Bundle`: как кортеж `(Pos, Vel, Hp)` раскладывается по колонкам |
| `query.rs` | `WorldQuery`: описание запросов, `QueryIter` — итератор |
| `world.rs` | `World`: связывает всё вместе, плюс тесты |

### Как работает удаление (`despawn`)

Чтобы не сдвигать весь массив, удаляемая строка меняется местами с последней («swap remove»), и длина уменьшается на 1. Сущность, которая была последней, теперь живёт в освободившейся строке, и её адрес обновляется.

Деструкторы компонентов (`Drop`) вызываются **после** того, как все колонки уже приведены в порядок. Если какой-то `Drop` запаникует, мир не сломается.

### Как работает добавление компонента (`insert`)

1. Находим архетип «текущий набор + новый тип». Ответ кэшируется в `add_edges`, поэтому поиск нужен только в первый раз.
2. Переносим все компоненты строки побайтно в новый архетип. Это перенос, а не копия: деструкторы не вызываются.
3. Дописываем новый компонент.

Это стоит около 0.1–0.2 мкс на сущность. Для флагов, которые меняются каждый шаг («бежит», «в бою»), дешевле держать поле `bool` внутри компонента.

## Детерминизм

- Номера сущностей выдаются одинаково при одинаковой последовательности команд: свободные слоты берутся по стеку.
- Архетипы обходятся в порядке создания, строки — по порядку. Внутренние `HashMap` используются только для поиска и никогда не обходятся.
- `world.hash_component::<T>()` считает хеш всех компонентов `T` вместе с их сущностями. Это контрольная точка для реплея. Компонент должен реализовать `Hash`; для полей `f32` пишите `self.x.to_bits().hash(h)`.
