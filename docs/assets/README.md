# Ассеты: как устроен крейт `rm_assets`

Этот раздел объясняет простыми словами, откуда в игре берутся модели и
текстуры и в каком виде их получает рендер.

## Зачем это нужно

Оригинальные модели и текстуры Medieval II в репозиторий класть нельзя.
Поэтому все ассеты проекта пока — **процедурные заглушки**: низкополигональные
модели и текстуры, которые собирает код. Красоты от них никто не ждёт.
Важно другое: они уже лежат в тех форматах и устроены по тем же
приёмам, на которых держался рендер оригинала:

- все текстуры упакованы в атлас, и модель знает только координаты своего
  куска (хак H-11);
- у каждой модели есть цепочка уровней детализации с жёсткими порогами и
  плоская картинка-импостор для дальних расстояний (хак H-15);
- для грязи, снега и крови есть маски, по которым шейдер подменяет цвет,
  без частиц и деформации моделей (хак H-12);
- свет и рельеф карты кампании запекаются в текстуры заранее (хак H-02),
  горы можно «вытянуть» по высоте (хак H-05).

Когда появятся настоящие модели от художника или из CC0-библиотек, их
нужно будет только положить в те же атласы и цепочки. Рендер менять не
придётся.

## Как этим пользоваться из кода

```rust
use rm_assets::{AssetLibrary, BuildOptions, ModelId};

// Собрать всё в памяти (детерминированно: то же зерно — те же байты).
let lib = AssetLibrary::build(&BuildOptions::default())?;

// Картинка атласа материалов — одна текстура на все модели.
let atlas = &lib.materials.image; // RGBA8, lib.materials.image.width × height

// LOD-цепочка копейщика и выбор уровня по расстоянию до камеры.
let chain = lib.model(ModelId::Spearman).unwrap();
match chain.select(distance_m, 1.0) {
    Some(level) => { /* рисовать chain.levels[level].geometry */ }
    None => { /* слишком далеко — не рисовать */ }
}

// Или сохранить в пакет и прочитать обратно (так будет делать игра).
let bytes = lib.to_pack()?;
let same = AssetLibrary::from_pack(&bytes)?;
```

Вершина (`rm_assets::Vertex`, 36 байт) — позиция, нормаль, UV в атласе и
флаг окраски фракции. Флаг совпадает с соглашением `rm_app`: 0 — цвет
текстуры, 1 — умножить на основной цвет фракции, 2 — на второй.

## Место в архитектуре

По [карте крейтов](../adr/crate-map.md) `rm_assets` — слой 1 (фундамент).
Он зависит только от `rm_core` (оттуда берутся `sin`/`cos`, одинаковые до
бита на всех платформах) и не тянет внешних библиотек. Симуляция
(`rm_battle`, `rm_campaign`) от него **не зависит**: ассеты нужны только
рендеру. Читать его будут `rm_crowd` (солдаты), `rm_city_render`
(постройки и стены), `rm_campaign_map` (почвы, lightmap), `rm_app`.

Сборщик в ADR назван `tools/rm_assetc`. Он живёт программой внутри
крейта (`src/bin/rm_assetc.rs`), так же как `rm_modcheck` живёт в `rm_data`:
workspace собирает только `crates/*`.

## Как проверяется

`cargo test -p rm_assets`:

- каждая модель на каждом уровне — правильный меш, и треугольников с
  уровнем становится меньше;
- солдаты укладываются в бюджет: не больше 400 / 120 / 40 треугольников
  на уровнях 0 / 1 / 2;
- все модели стоят на земле (низ на y = 0);
- нормали коробок, цилиндров, конусов, крыш смотрят наружу;
- каждый треугольник читает текстуру только из одного куска атласа;
- атлас масок разложен в точности как атлас материалов;
- куски атласа не перекрываются, рамка повторяет край;
- почвы бесшовные; одинаковое зерно даёт одинаковые текстуры;
- пакет переживает запись и чтение без потерь; испорченный, обрезанный
  или чужой версии пакет даёт понятную ошибку;
- сборка библиотеки дважды даёт одинаковые байты.

## Что дальше

- **Подключение к битве.** Сейчас `rm_app` рисует свои коробочные модели
  (`crates/rm_app/src/render/mesh.rs`) без текстур. Чтобы перейти на
  атлас, рендеру битвы нужна привязка текстуры и UV в шейдере — это
  работа владельца `rm_app` или будущего `rm_crowd`; ассеты для этого
  готовы.
- **Пороги LOD из файла.** Значения в `LodThresholds::default()` — технические
  умолчания. По [контракту моддинга](../adr/modding-contract.md) их будет
  переопределять `descr_rm_lod.txt`; его разбор — задача `rm_data`.
- **Анимация, запечённая в текстуры (H-14).** Пока солдаты анимируются
  формулой в вершинном шейдере `rm_app`. Запекание кадров в текстуру —
  следующий шаг этого крейта.
- **Настоящие модели.** Чтение моделей из файлов (например, glTF из
  CC0-библиотек) и их упаковка в те же атласы и цепочки.
